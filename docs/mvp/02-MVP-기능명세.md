# MVP 기능명세

## 1. 문서 목적

이 문서는 MVP에서 구현할 사용자 기능과 동작 규칙을 정의한다. 구현 중 애매한 판단이 생기면 이 문서를 기준으로 범위를 결정한다.

## 2. 공통 정의

### 시간 단위

- 기본 기록 단위는 10분이다.
- 모든 시작 시간과 종료 시간은 10분 단위로 스냅된다.
- 예: 09:00, 09:10, 09:20은 유효하고 09:05는 MVP 저장 단위로 사용하지 않는다.

### 하루 표시 범위

- 기본 표시 범위는 05:00-24:00이다.
- 설정에서 00:00-24:00 전체 보기로 확장할 수 있다.
- MVP에서 24:00은 다음 날 00:00과 같은 끝 시각으로 취급한다.

### 주간 기준

- 기본 주 시작 요일은 월요일이다.
- 한 주는 월요일 00:00부터 일요일 24:00까지다.
- 화면의 기본 진입 주는 현재 날짜가 포함된 주다.

### 플랫폼별 역할

| 플랫폼 | 역할 |
|---|---|
| 모바일 앱 | 기록 입력, 사진첩 접근, 사진 매칭, 회고 작성 |
| 데스크톱 웹 | 동기화된 기록 열람, 주간 회고, CSV 내보내기 |

## 4. F-01 계정 생성과 로그인

### 설명

사용자는 모바일 앱과 데스크톱 웹에서 같은 기록을 보기 위해 계정으로 로그인한다.

### 수용 기준

- Supabase Auth 기반 이메일/비밀번호 계정 생성과 로그인을 제공한다.
- 소셜 로그인은 MVP 후속 범위로 둔다.
- 로그인한 사용자만 자신의 기록을 볼 수 있다.
- 로그아웃할 수 있다.
- 모바일 앱은 로그인 세션을 안전하게 저장한다.
- 데스크톱 웹은 로그인 후 동기화된 기록만 보여준다.

## 5. F-02 모바일/웹 동기화

### 설명

모바일에서 입력한 기록이 서버에 동기화되고, 데스크톱 웹에서 열람된다.

### 수용 기준

- 모바일 앱은 오프라인 상태에서도 기존 기록 조회와 편집이 가능하다.
- 네트워크가 복구되면 변경 사항을 서버에 동기화한다.
- 데스크톱 웹은 서버에 동기화된 기록을 조회한다.
- 동일 기록의 수정 충돌은 MVP에서 `updatedAt`이 최신인 변경을 우선한다.
- 동기화 실패 시 모바일 앱에서 상태를 표시한다.

## 6. F-03 이번 주 보기

### 설명

사용자는 현재 주의 시간 사용을 7일 단위로 확인한다.

### 수용 기준

- 이번 주의 월요일부터 일요일까지 7일이 표시된다.
- 오늘 날짜는 시각적으로 구분된다.
- 이전 주와 다음 주로 이동할 수 있다.
- 오늘 버튼을 누르면 현재 주로 돌아온다.

## 7. F-04 10분 블록 그리드

### 설명

사용자는 하루를 10분 단위 블록으로 나눈 그리드에서 기록 상태를 확인한다.

### 수용 기준

- 7일 x 표시 시간대의 10분 블록이 렌더링된다.
- 기본 범위 05:00-24:00 기준 하루 114개 블록이 표시된다.
- 전체 범위 00:00-24:00 기준 하루 144개 블록이 표시된다.
- 기록된 블록은 카테고리 색상으로 표시된다.
- 미기록 블록은 중립 색상으로 표시된다.
- 사진이 매칭된 기록에는 작은 썸네일 표시가 가능하다.

## 8. F-05 모바일 시간 범위 선택

### 설명

사용자는 모바일 앱에서 드래그, 탭, 직접 입력 중 하나로 시간 범위를 선택한다.

### 수용 기준

- 같은 날짜 안에서 연속된 시간 범위를 선택할 수 있다.
- 선택 시작과 끝이 바뀌어도 올바른 시간 범위로 정렬된다.
- 선택된 범위는 임시 하이라이트로 표시된다.
- 터치 드래그가 불편한 경우 시작/종료 시간 직접 입력을 제공한다.
- MVP에서는 여러 날짜를 한 번에 가로질러 선택하지 않는다.

## 9. F-06 카테고리 적용

### 설명

사용자는 선택한 시간 범위에 카테고리를 적용한다.

### 사용자 흐름

1. 사용자가 시간 범위를 선택한다.
2. 카테고리 팔레트가 활성화된다.
3. 사용자가 카테고리를 선택한다.
4. 선택 범위가 해당 카테고리 색상으로 저장된다.

### 수용 기준

- 카테고리 팔레트에는 사용자가 생성한 활성 카테고리만 표시한다.
- 생성된 카테고리가 없으면 예시 카테고리를 참고해 새 카테고리를 만들도록 안내한다.
- 선택 범위가 없으면 카테고리 적용 버튼은 비활성 상태로 보인다.
- 카테고리를 적용하면 기록이 즉시 그리드에 반영된다.
- 기록 저장 후 선택 상태는 해제된다.
- 최근 사용 카테고리가 팔레트 상단에 표시된다.

## 10. F-07 기록 추가

### 설명

사용자는 실제 시간 사용 기록을 추가한다.

### 입력값

- 날짜
- 시작 시간
- 종료 시간
- 카테고리
- 메모

### 수용 기준

- 시작 시간은 종료 시간보다 빨라야 한다.
- 시작/종료 시간은 10분 단위여야 한다.
- 카테고리는 필수다.
- 메모는 선택 입력이다.
- 저장 즉시 모바일 그리드와 합계가 갱신된다.
- 네트워크가 가능하면 서버 동기화 큐에 반영된다.

## 11. F-08 기록 수정

### 설명

사용자는 기존 기록의 시간, 카테고리, 메모를 수정한다.

### 수용 기준

- 기록 블록을 선택하면 편집 화면을 열 수 있다.
- 시작 시간, 종료 시간, 카테고리, 메모를 수정할 수 있다.
- 수정 후 그리드와 합계가 갱신된다.
- 잘못된 시간 범위는 저장할 수 없다.
- 사진 매칭 결과는 수정된 시간 범위에 맞게 다시 계산된다.

## 12. F-09 기록 삭제

### 설명

사용자는 잘못 입력한 기록을 삭제한다.

### 수용 기준

- 기록 편집 화면에서 삭제할 수 있다.
- 삭제 전 확인 절차를 제공한다.
- 삭제 후 해당 시간 범위는 미기록 상태로 돌아간다.
- 삭제 후 그리드와 합계가 갱신된다.
- 연결된 사진 참조는 삭제하거나 미연결 상태로 변경한다.

## 13. 기록 겹침 처리 규칙

MVP에서는 실제 기록끼리 같은 시간에 겹치지 않는다.

### 새 기록이 기존 기록과 겹칠 때

새 기록을 우선한다.

예:

- 기존 기록: 09:00-10:00 공부
- 새 기록: 09:30-10:30 운동

결과:

- 09:00-09:30 공부
- 09:30-10:30 운동

### 기존 기록이 새 기록에 완전히 포함될 때

기존 기록은 삭제되고 새 기록으로 대체된다.

### 기존 기록이 새 기록의 중간을 지나갈 때

기존 기록은 앞뒤로 분할된다.

## 14. F-10 카테고리 관리

### 설명

사용자는 자신의 삶의 영역에 맞게 카테고리를 관리한다.

### 예시 카테고리

신규 사용자에게는 다음 예시 카테고리를 생성 힌트로 보여준다. 예시 카테고리는 실제 사용자 데이터로 자동 생성하지 않으며, 사용자가 선택해 저장한 뒤에만 기록에 적용할 수 있다.

- 수면
- 이동/식사
- 공부/주요 업무
- 자기개발
- 영적시간
- 운동/건강
- 가족/관계
- 집안일/심부름
- 휴식
- 낭비한 시간

### 입력값

- 이름
- 색상
- 이모지
- 주간 목표 시간
- 표시 순서

### 수용 기준

- 카테고리를 추가할 수 있다.
- 카테고리 이름, 색상, 이모지를 수정할 수 있다.
- 사용자는 예시 카테고리와 무관하게 자신만의 카테고리를 만들 수 있다.
- 카테고리는 사용자 소유 데이터이며, 공유 기능을 별도로 제공하지 않는 한 다른 사용자와 공유되지 않는다.
- 카테고리 그룹화를 위한 별도 속성은 제공하지 않는다.
- 같은 색상을 쓰는 카테고리는 통계에서 같은 색상 그룹으로 묶인다.
- 사용 중인 카테고리를 삭제하려고 하면 확인 절차를 제공한다.
- 삭제된 카테고리의 기존 기록은 보존하되, 보관 상태로 표시한다.
- 카테고리 변경은 모바일 앱과 데스크톱 웹에 동기화된다.

## 15. F-11 일간 합계

### 설명

사용자는 특정 날짜의 시간 사용 합계를 확인한다.

### 수용 기준

- 날짜별 색상 기준 총 시간이 표시된다.
- 날짜별 카테고리 이름 기준 총 시간이 표시된다.
- 날짜별 이모지 기준 총 시간이 표시된다.
- 날짜별 미기록 시간이 표시된다.
- 가장 많이 기록된 카테고리가 표시된다.
- 전체 표시 시간대 기준 기록 완성률이 표시된다.
- 사진이 있는 기록 수를 보조 정보로 표시할 수 있다.

## 16. F-12 주간 합계

### 설명

사용자는 한 주의 카테고리별 총 시간을 확인한다.

### 수용 기준

- 색상별 주간 총 시간이 표시된다.
- 카테고리 이름별 주간 총 시간이 표시된다.
- 이모지별 주간 총 시간이 표시된다.
- 선택한 집계 기준별 비율이 표시된다.
- 주간 미기록 시간이 표시된다.
- 주간 기록 완성률이 표시된다.
- 낭비한 시간 카테고리는 별도로 눈에 띄게 표시한다.

## 17. F-13 미기록 시간 계산

### 설명

미기록 시간은 표시 시간대 중 실제 기록이 없는 시간이다.

### 계산 규칙

```text
미기록 시간 = 표시 대상 총 시간 - 실제 기록 총 시간
```

### 수용 기준

- 일간 미기록 시간을 계산한다.
- 주간 미기록 시간을 계산한다.
- 표시 시간대가 바뀌면 미기록 시간도 다시 계산한다.
- 템플릿은 미기록 시간 계산에서 제외한다.

## 18. F-14 주간 회고 메모

### 설명

사용자는 한 주에 대한 회고를 작성한다.

### 입력값

- 이번 주 요약
- 잘한 점
- 아쉬운 점
- 다음 주 집중할 것

### 수용 기준

- 주 단위로 회고 메모가 저장된다.
- 주를 이동하면 해당 주의 회고가 표시된다.
- 모바일 앱과 데스크톱 웹에서 같은 회고를 볼 수 있다.

## 19. F-15 CSV 내보내기

### 설명

사용자는 자신의 시간 기록 데이터를 CSV로 내보낼 수 있다.

### 내보내기 범위

- 현재 주
- 전체 기록

### CSV 필드

- date
- startTime
- endTime
- durationMinutes
- categoryName
- categoryColor
- categoryEmoji
- note
- source
- photoCount
- createdAt
- updatedAt

### 수용 기준

- CSV 파일을 다운로드할 수 있다.
- 한글 카테고리명이 깨지지 않아야 한다.
- 현재 주 내보내기와 전체 내보내기를 구분할 수 있다.
- 사진 원본이나 로컬 사진 경로는 CSV에 포함하지 않는다.

## 20. F-16 사진첩 권한

### 설명

사용자는 모바일 앱에서 사진첩 접근 권한을 허용하거나 거부할 수 있다.

### 수용 기준

- 사진 기능 사용 전에 권한 요청 이유를 명확히 설명한다.
- 사용자가 권한을 거부해도 시간 기록 기능은 정상 동작한다.
- 제한된 사진 접근 권한만 허용된 경우, 허용된 사진만 매칭 대상으로 사용한다.
- 권한 상태는 설정 화면에서 확인할 수 있다.
- 권한 재요청 또는 시스템 설정 이동 경로를 제공한다.

## 21. F-17 사진 시간대 매칭

### 설명

모바일 앱은 사진의 촬영 시각을 기준으로 기록 시간 범위에 해당하는 사진을 찾아 작은 썸네일로 표시한다.

### 매칭 규칙

```text
사진 촬영 시각 >= 기록 시작 시각
사진 촬영 시각 < 기록 종료 시각
```

### 수용 기준

- 모바일 앱은 특정 날짜의 사진만 우선 조회한다.
- 기록 시간 범위 안에 촬영된 사진을 해당 기록에 연결한다.
- 한 기록에 여러 사진이 있으면 최대 3개의 썸네일을 먼저 표시한다.
- 사용자는 기록 상세에서 연결된 사진 목록을 볼 수 있다.
- 사용자는 특정 사진을 숨기거나 연결 해제할 수 있다.
- 사진 원본은 자동 업로드하지 않는다.
- 데스크톱 웹 표시는 동기화된 작은 썸네일이 있을 때만 가능하다.

## 22. F-18 데스크톱 웹 열람

### 설명

사용자는 데스크톱 브라우저에서 모바일 앱으로 기록한 주간 데이터를 열람한다.

### 수용 기준

- 로그인 후 자신의 주간 기록을 볼 수 있다.
- 데스크톱 웹에서 주간 합계와 회고를 볼 수 있다.
- 데스크톱 웹에서 CSV를 내보낼 수 있다.
- 데스크톱 웹은 모바일 사진첩을 직접 읽지 않는다.
- 동기화된 썸네일이 있으면 기록 옆에 표시한다.
- MVP에서 데스크톱 웹 입력 기능은 제한해도 된다.

## 23. F-19 템플릿 관리

### 설명

사용자는 반복되는 하루 루틴을 템플릿으로 저장하고 불러올 수 있다.

### 후속 템플릿 범위

F-19는 P2 후속 범위다. MVP 완료 기준에는 포함하지 않는다.

- 템플릿 추가
- 템플릿 수정
- 템플릿 삭제
- 특정 날짜에 템플릿 적용

### 수용 기준

- 템플릿은 실제 기록과 구분되어 저장된다.
- 템플릿을 날짜에 적용하면 실제 기록으로 복사된다.
- 템플릿 적용 시 기존 기록과 겹치면 사용자 확인 후 덮어쓴다.
- 계획 대비 실제 비교는 MVP에서 제공하지 않는다.

## 24. MVP에서 제공하지 않는 기능

### F-20 카테고리 색상/이모지 추천

#### 설명

사용자가 카테고리 이름만 입력하면 앱이 어울리는 색상과 이모지를 추천한다.

#### 사용자 흐름

1. 사용자가 카테고리 추가 화면을 연다.
2. 사용자가 이름을 입력한다.
3. 앱이 이름에 맞는 색상과 이모지 후보를 보여준다.
4. 사용자는 추천값을 그대로 쓰거나 직접 수정한다.
5. 저장된 카테고리는 기존 `color`, `emoji` 필드에 저장된다.

#### 수용 기준

- 카테고리 이름 입력 후 색상과 이모지가 자동 추천된다.
- 추천값은 사용자가 언제든 수동 변경할 수 있다.
- 추천 실패 시 기본 색상과 기본 이모지를 제공한다.
- 이미 사용 중인 색상과 너무 비슷한 색상은 가능하면 피한다.
- MVP에서는 구현하지 않고 후속 기능으로 둔다.

### 기타 제외 기능

- 사진첩 자동 접근
- 사진 원본 자동 업로드
- 백그라운드 전체 사진 스캔
- 위치 기반 자동 기록
- 실시간 타이머
- 알림
- 반복 일정 자동 생성
- 캘린더 연동
- AI 요약
- 여러 사용자 공유
