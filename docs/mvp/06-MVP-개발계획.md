# MVP 개발계획

## 1. 문서 목적

이 문서는 React Native + Expo 기반 모바일 앱과 데스크톱 companion web을 구현하기 위한 마일스톤, 우선순위, 검증 기준을 정의한다.

## 2. 개발 목표

MVP 개발의 목표는 다음 네 가지 사용 흐름을 끝까지 동작하게 만드는 것이다.

1. 모바일 앱에서 시간을 기록한다.
2. 기록 시간대에 찍힌 사진을 작은 단서로 확인한다.
3. 기록이 Supabase에 저장된다.
4. 데스크톱 웹에서 같은 주간 기록을 열람하고 회고한다.

## 3. 전체 일정

권장 일정은 6주다.

| 주차 | 목표 |
|---|---|
| 1주차 | 모노레포, Expo 앱, 웹 앱, Supabase 기반 |
| 2주차 | 도메인 모델, 서버 스키마, Supabase 기록 CRUD, 겹침 처리 |
| 3주차 | 모바일 주간/오늘 화면, 시간 선택, 카테고리 적용 |
| 4주차 | 인증, 서버 데이터 연결, 데스크톱 웹 열람 |
| 5주차 | 사진첩 권한, 사진 매칭, 썸네일 표시 |
| 6주차 | 회고, CSV, 모바일 QA, 배포 준비 |

개인 개발이라면 6주도 타이트하다. 오프라인 기록과 동기화 큐는 후속으로 미루고, MVP는 Supabase-first 기록 UX를 먼저 안정화한다.

구현 전에 제품 범위와 기술 결정을 고정한다.

### 작업

- MVP 정의서 확정
- 기능명세 확정
- 화면설계 확정
- 데이터모델 확정
- Supabase 사용 확정
- Supabase Auth 이메일/비밀번호 로그인 우선 확정
- Expo development build, EAS 내부 테스트, Vercel 웹 배포 확정
- 월요일 주 시작, 기본 표시 시간대 05:00-24:00 확정
- 썸네일 동기화 기본 비활성 확정
- 사진 원본 업로드 제외 원칙 확정

### 완료 기준

- 1차 플랫폼이 React Native + Expo로 확정되어 있다.
- 데스크톱 웹은 companion web으로 정의되어 있다.
- 사진첩 기능은 모바일 전용으로 정의되어 있다.
- 템플릿, 추천, 알림, 타이머, AI 회고는 후속 범위로 분리되어 있다.

## 5. 마일스톤 1: 프로젝트 기반

### 목표

모바일 앱, 웹 앱, 공통 도메인 패키지가 실행되는 상태를 만든다.

### 작업

- 모노레포 구성
- Expo + TypeScript 앱 생성
- Next.js + TypeScript 웹 앱 생성
- 공통 도메인 패키지 생성
- Supabase 프로젝트 설정
- 인증 기본 연결
- 기본 레이아웃 구성
- 도메인 타입 정의
- 시간 유틸리티 작성

### 주요 산출물

- 모바일 앱 첫 화면
- 데스크톱 웹 로그인 화면
- 공통 타입과 시간 유틸리티

### 테스트

- 모바일 앱이 실행된다.
- 웹 앱이 실행된다.
- 같은 도메인 타입을 모바일과 웹에서 사용할 수 있다.
- 시간 유틸리티가 10분 단위 규칙을 통과한다.

## 6. 마일스톤 2: 데이터와 기록 CRUD

### 목표

기록 데이터의 생성, 수정, 삭제와 겹침 처리를 완성한다.

### 작업

- Supabase 테이블 스키마 작성
- 기본 설정과 예시 카테고리 정책 정의
- Supabase 기록 저장 계층 작성
- 인증 세션 기반 사용자 ID 처리
- 기록 추가
- 기록 수정
- 기록 삭제
- 기록 겹침 처리
- 카테고리 관리 기본

### 주요 산출물

- Supabase 기록 저장
- 서버 스키마
- 겹침 처리 로직

### 테스트

- 기본 설정의 사용자 초기화 정책과 예시 카테고리 표시 정책이 정의되어 있다.
- 기록을 추가/수정/삭제할 수 있다.
- 새 기록이 기존 기록과 겹칠 때 새 기록이 우선된다.
- 기록 CRUD가 Supabase에 저장되고 재조회된다.
- 네트워크 또는 서버 저장 실패가 사용자에게 표시된다.

## 7. 마일스톤 3: 모바일 기록 UX

### 목표

제품의 핵심인 모바일 10분 블록 기록 경험을 완성한다.

### 작업

- 이번 주 계산
- 오늘 상세 화면
- 주간 그리드 렌더링
- 오늘 표시
- 터치 기반 시간 범위 선택
- 시작/종료 시간 직접 입력
- 카테고리 팔레트
- 선택 범위에 카테고리 적용
- 기록 편집 화면

### 주요 산출물

- 모바일 이번 주 화면
- 모바일 오늘 상세
- 기록 편집 화면

### 테스트

- 모바일에서 시간 범위를 선택할 수 있다.
- 카테고리를 적용하면 기록이 생성된다.
- 기록을 선택해 수정할 수 있다.
- 좁은 화면에서 UI 요소가 겹치지 않는다.

## 8. 마일스톤 4: 인증, 서버 연결, 데스크톱 웹

### 목표

모바일과 데스크톱 웹이 같은 Supabase 데이터를 열람할 수 있게 만든다.

### 작업

- 모바일 로그인
- 웹 로그인
- 사용자별 데이터 격리
- 신규 사용자 기본 설정 초기화
- 모바일 Supabase 저장 흐름
- 서버 데이터 공유
- 데스크톱 주간 보기
- 데스크톱 주간 합계
- 회고 메모 서버 저장

### 주요 산출물

- 계정 기반 모바일 앱
- 데스크톱 companion web
- 모바일-웹 서버 데이터 공유

### 테스트

- 모바일에서 로그인할 수 있다.
- 웹에서 같은 계정으로 로그인할 수 있다.
- 신규 사용자 최초 접속 시 기본 설정이 사용자 데이터로 생성되고 예시 카테고리는 생성 힌트로 표시된다.
- 모바일에서 만든 기록이 웹에 보인다.
- 웹에서 수정한 회고가 모바일에 보인다.
- 네트워크 또는 서버 저장 실패가 사용자에게 표시된다.

## 9. 마일스톤 5: 사진첩 권한과 사진 매칭

### 목표

기록 시간대에 찍힌 사진을 모바일에서 작은 단서로 보여준다.

### 작업

- 사진 권한 안내 화면
- 사진 권한 요청
- 권한 상태 표시
- 날짜별 사진 조회
- 촬영 시각 기반 기록 매칭
- 로컬 썸네일 생성
- 기록 블록 사진 표시
- 기록 상세 사진 목록
- 사진 숨김/연결 해제
- 선택적 썸네일 동기화

### 주요 산출물

- 사진 권한 설정
- 기록 시간대 사진 썸네일
- PhotoReference 모델

### 테스트

- 권한 거부 시 기록 기능이 정상 동작한다.
- 권한 허용 시 해당 날짜 사진을 조회한다.
- 기록 시간 안에 촬영된 사진만 매칭된다.
- 원본 사진이 자동 업로드되지 않는다.
- 썸네일 동기화를 켠 경우 웹에서 작은 썸네일을 볼 수 있다.

## 10. 마일스톤 6: 회고, CSV, QA

### 목표

MVP를 실제 검증 가능한 상태로 마감한다.

### 작업

- 일간 색상별, 카테고리 이름별, 이모지별 합계
- 주간 색상별, 카테고리 이름별, 이모지별 합계
- 기록 완성률
- 미기록 시간
- 낭비한 시간 표시
- 주간 회고 메모
- CSV 내보내기
- 저장 실패 상태 표시
- 모바일 QA
- 웹 QA
- 내부 테스트 빌드

### 주요 산출물

- 주간 회고 화면
- CSV 파일
- 내부 테스트 가능한 모바일 빌드
- 배포 가능한 웹 빌드

### 테스트

- 합계가 기록 변경에 따라 갱신된다.
- 주간 회고 메모가 모바일과 웹에서 같은 서버 데이터로 보인다.
- CSV 한글이 깨지지 않는다.
- 모바일 사진 기능을 꺼도 앱이 정상 동작한다.
- 주요 화면이 모바일과 데스크톱에서 깨지지 않는다.

## 12. MVP QA 체크리스트

### 기록

- [ ] 모바일에서 시간 범위를 선택할 수 있다.
- [ ] 선택 범위에 카테고리를 적용할 수 있다.
- [ ] 기록을 수정할 수 있다.
- [ ] 기록을 삭제할 수 있다.
- [ ] 겹치는 기록이 올바르게 처리된다.

### 서버 연결

- [ ] 모바일에서 로그인할 수 있다.
- [ ] 웹에서 같은 계정으로 로그인할 수 있다.
- [ ] 모바일 기록이 웹에 표시된다.
- [ ] 네트워크 또는 서버 저장 실패가 사용자에게 표시된다.
- [ ] 사용자별 데이터가 분리된다.

### 사진

- [ ] 사진 권한 요청 전 이유를 설명한다.
- [ ] 권한 거부 시 앱이 정상 동작한다.
- [ ] 권한 허용 시 사진을 날짜 기준으로 조회한다.
- [ ] 기록 시간대 사진만 매칭된다.
- [ ] 원본 사진이 자동 업로드되지 않는다.
- [ ] 썸네일 동기화 설정을 끌 수 있다.

### 통계

- [ ] 일간 색상별, 카테고리 이름별, 이모지별 합계가 맞다.
- [ ] 주간 색상별, 카테고리 이름별, 이모지별 합계가 맞다.
- [ ] 미기록 시간이 맞다.
- [ ] 기록 완성률이 맞다.

### 회고와 내보내기

- [ ] 주간 회고 메모가 저장된다.
- [ ] 주를 이동하면 해당 주 회고가 보인다.
- [ ] 현재 주 CSV를 내보낼 수 있다.
- [ ] 전체 CSV를 내보낼 수 있다.
- [ ] CSV 한글이 깨지지 않는다.

### 모바일/웹 UI

- [ ] 모바일에서 핵심 기록 흐름이 가능하다.
- [ ] 카테고리 선택 영역이 터치하기 쉽다.
- [ ] 화면 요소가 겹치지 않는다.
- [ ] 데스크톱 웹에서 주간 기록을 읽기 쉽다.

## 13. 주요 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 모바일 주간 그리드가 너무 작다 | 오늘 중심 입력과 가로 스크롤을 병행한다 |
| 터치 드래그가 불편하다 | 시작/종료 시간 직접 입력을 보조로 제공한다 |
| 오프라인 저장과 동기화 큐가 MVP를 무겁게 만든다 | MVP는 Supabase-first로 구현하고 오프라인 기록은 후속으로 분리한다 |
| 사진 권한이 거부된다 | 사진 없이도 핵심 기록 기능이 완전하게 동작하게 한다 |
| 사진 원본 업로드에 대한 불신이 생긴다 | 원본 자동 업로드 제외 원칙을 온보딩과 설정에 명확히 표시한다 |
| 웹에서 사진이 안 보인다는 혼란이 생긴다 | 웹은 동기화된 썸네일만 표시 가능하다고 안내한다 |

## 14. 출시 기준

다음 조건을 만족하면 MVP를 내부 테스트 가능한 상태로 본다.

- P0 기능이 모두 동작한다.
- 모바일 기록 입력이 안정적이다.
- 모바일과 웹이 같은 서버 기록을 조회한다.
- 사진 권한 허용/거부 흐름이 모두 정상이다.
- 사진 원본이 자동 업로드되지 않는다.
- 웹에서 주간 기록과 회고를 열람할 수 있다.
- CSV 내보내기가 동작한다.
- QA 체크리스트의 핵심 항목을 통과한다.

## 15. 출시 후 검증 질문

MVP 배포 후에는 다음 질문에 답한다.

- 첫 기록을 추가하는 데 얼마나 걸리는가?
- 사용자가 하루 기록을 끝까지 채울 수 있는가?
- 사진 썸네일이 실제 회고에 도움이 되는가?
- 사진 권한 요청이 사용자에게 부담스럽지 않은가?
- 데스크톱 웹 열람이 실제로 사용되는가?
- 카테고리 생성 시 색상/이모지 추천이 입력 비용을 줄이는가?
- 미기록 시간이 줄어드는가?
- 사용자가 다음 주에도 다시 기록하려고 하는가?

이 질문에 대한 답을 바탕으로 다음 버전에서 타이머, 알림, 템플릿, 카테고리 추천, 캘린더 연동, AI 회고 중 무엇을 먼저 할지 결정한다.
