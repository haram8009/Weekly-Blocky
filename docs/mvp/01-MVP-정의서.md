# MVP 정의서

## 1. 문서 목적

이 문서는 `10분 단위 위클리 타임블로킹 다이어리 앱`의 MVP 범위와 성공 기준을 정의한다.

MVP의 핵심 가설은 다음이다.

> 사용자는 실제로 쓴 시간을 10분 단위 색상 블록으로 빠르게 기록하고, 그 시간대에 찍힌 사진을 작은 단서로 함께 보면 하루와 일주일의 시간 사용을 더 쉽게 기억하고 회고할 수 있다.

## 2. 제품 정의

### 제품 한 줄 설명

모바일에서 10분 단위 색상 블록으로 실제 시간 사용을 기록하고, 데스크톱 웹에서도 주간 기록을 열람할 수 있는 개인 시간 다이어리.

### 제품 포지션

- 캘린더 대체 앱이 아니다.
- 할 일 관리 앱이 아니다.
- 계획 중심 타임블로킹 앱이 아니다.
- 실제 시간 사용을 빠르게 기록하고 주간 단위로 회고하는 시간 가계부다.
- 사진은 기록의 주인공이 아니라, 특정 시간대를 기억하게 해주는 보조 단서다.

## 3. 플랫폼 결정

### 최종 선택

MVP의 최종 방향은 **React Native + Expo 기반 모바일 앱 우선**이다.

데스크톱에서는 별도의 네이티브 앱을 만들지 않고, 같은 계정 데이터를 읽는 **companion web**을 제공한다.

```text
모바일 앱: React Native + Expo
데스크톱 웹: React/Next.js 기반 열람용 웹
백엔드: Supabase Auth, Postgres, Storage
인증: 이메일/비밀번호 우선, 소셜 로그인 후속
사진 기능: 모바일 앱에서만 사진첩 접근
```

### 선택 이유

- 서비스의 중심 사용 환경은 모바일이다.
- 사진첩 접근, 사진 권한, 촬영 시각 기반 매칭은 PWA보다 네이티브 앱 계열이 적합하다.
- Flutter도 가능하지만, 데스크톱 웹 열람과 React 기반 웹 확장까지 고려하면 React Native + Expo가 더 일관적이다.
- PWA는 사용자가 직접 파일을 고르는 흐름에는 적합하지만, 모바일 사진첩을 날짜/시간 기준으로 자연스럽게 읽는 핵심 경험에는 부적합하다.

### 데스크톱 웹의 역할

데스크톱 웹은 기록 입력의 주 사용처가 아니라 열람과 회고를 위한 보조 화면이다.

- 주간 기록 열람
- 색상별, 카테고리 이름별, 이모지별 합계 확인
- 회고 메모 작성 또는 수정
- CSV 내보내기
- 동기화된 사진 썸네일 표시

데스크톱 웹은 사용자의 로컬 모바일 사진첩을 직접 읽지 않는다.

## 4. MVP 목표

MVP는 다음 행동이 실제로 매끄러운지 검증한다.

1. 모바일에서 시간 범위를 빠르게 선택한다.
2. 선택한 시간에 카테고리 색상을 적용한다.
3. 해당 시간대에 찍힌 사진을 작은 썸네일로 확인한다.
4. 주간 합계를 보고 시간 사용 패턴을 이해한다.
5. 데스크톱 웹에서 같은 주간 기록을 열람한다.

## 5. 1차 타깃 사용자

MVP는 다음 사용자에게 맞춘다.

- 하루가 끝나면 시간을 어디에 썼는지 흐릿하게 느끼는 개인
- 공부, 일, 자기계발, 운동, 영적시간, 휴식, 낭비 시간을 구분하고 싶은 사용자
- 모바일에서 기록하고, 데스크톱에서는 넓은 화면으로 주간 패턴을 보고 싶은 사용자
- 사진을 보면 그때 무엇을 했는지 더 잘 기억하는 사용자
- 노션, 종이 플래너, 일반 캘린더로 실제 시간 기록을 하다가 입력 비용 때문에 포기한 사용자

## 6. 핵심 사용자 문제

| 문제 | MVP에서의 해결 방식 |
|---|---|
| 실제로 뭘 했는지 기억하기 어렵다 | 10분 단위 블록으로 하루를 시각화한다 |
| 시간 기록 앱은 입력이 귀찮다 | 드래그 선택 후 카테고리 선택으로 기록한다 |
| 캘린더에는 실제 행동 기록이 남지 않는다 | 계획이 아니라 실제 기록을 기본 데이터로 저장한다 |
| 시간이 어디로 샜는지 보기 어렵다 | 미기록/낭비 카테고리를 명시적으로 집계한다 |
| 기록 당시 맥락이 잘 떠오르지 않는다 | 해당 시간대 사진 썸네일을 보조 기억 단서로 보여준다 |
| 모바일에서 기록한 내용을 데스크톱에서 보기 어렵다 | 계정 기반 동기화와 데스크톱 웹 열람을 제공한다 |

## 7. MVP 포함 범위

### 반드시 포함

- Expo 기반 모바일 앱
- 데스크톱 companion web
- 계정 생성과 로그인
- 모바일/웹 간 기본 동기화
- 이번 주 10분 블록 그리드
- 모바일 중심 시간 범위 선택
- 카테고리 팔레트
- 기록 추가, 수정, 삭제
- 카테고리 추가, 수정, 삭제
- 카테고리 색상 지정
- 일간 색상별, 카테고리 이름별, 이모지별 합계
- 주간 색상별, 카테고리 이름별, 이모지별 합계
- 미기록 시간 집계
- 주간 회고 메모
- CSV 내보내기
- 모바일 사진첩 권한 요청
- 촬영 시각 기반 사진 매칭
- 기록 시간대 사진 썸네일 표시

### 후속 후보

아래 항목은 핵심 기록 UX와 동기화가 안정화된 뒤 후속 범위로 분리한다. M0 기준 MVP 필수 구현 대상이 아니다.

- 템플릿 추가, 수정, 삭제
- 간단한 목표 대비 실제 시간 표시
- 주 시작 요일 설정
- 00:00-24:00 전체 보기 전환
- 동기화된 썸네일의 데스크톱 웹 표시
- 사진 매칭 수동 해제 또는 숨김 처리

## 8. MVP 제외 범위

다음은 MVP에서 제외한다.

- PWA를 메인 앱으로 제공
- 웹에서 직접 모바일 사진첩 읽기
- 사진 원본 자동 업로드
- 사진 원본을 서버에 저장
- 백그라운드 전체 사진첩 스캔
- 위치 정보 기반 기록
- Google Calendar, Apple Calendar 연동
- 알림
- 위젯
- AI 회고 요약
- 카테고리 이름 기반 색상/이모지 추천
- Apple Watch 또는 웨어러블 기록
- 팀, 공유, 협업 기능
- 결제

## 9. 기능 우선순위

| 우선순위 | 기능 | 이유 |
|---|---|---|
| P0 | 모바일 앱 기본 구조 | 서비스의 1차 사용 환경 |
| P0 | 계정/동기화 | 데스크톱 웹 열람의 전제 |
| P0 | 10분 블록 기록 | 제품의 핵심 시각화 |
| P0 | 시간 범위 선택 | 입력 비용을 낮추는 핵심 UX |
| P0 | 카테고리 색상 적용 | 시간 사용을 직관적으로 인식하는 핵심 장치 |
| P0 | 기록 CRUD | 실제 사용 기록의 기본 기능 |
| P1 | 데스크톱 웹 열람 | 넓은 화면에서 주간 회고 가능 |
| P1 | 주간/일간 합계 | 회고와 인사이트의 최소 단위 |
| P1 | 사진첩 매칭 | 기록 당시 맥락을 보강하는 차별화 기능 |
| P1 | 주간 회고 메모 | 다이어리 포지션 강화 |
| P1 | CSV 내보내기 | 개인 데이터 소유권과 백업 |
| P2 | 템플릿 CRUD | 반복 루틴 입력 비용 감소 |
| P3 | 카테고리 색상/이모지 추천 | 카테고리 생성 입력 비용 감소 |

## 9.1 후속 기능 후보

### 카테고리 색상/이모지 추천

사용자가 새 카테고리를 만들 때 이름만 입력하면 앱이 어울리는 색상과 이모지를 추천한다.

예:

- `운동` 입력 시 초록 계열 색상과 운동 관련 이모지 추천
- `영적시간` 입력 시 차분한 색상과 묵상/기도 관련 이모지 추천
- `낭비한 시간` 입력 시 경고성이 있지만 과도하게 자극적이지 않은 색상과 이모지 추천

이 기능은 MVP 필수 범위가 아니다. 예시 카테고리를 참고한 수동 카테고리 생성과 수동 색상/이모지 선택이 충분히 안정화된 뒤 추가한다.

## 10. 성공 기준

### 사용성 기준

- 사용자는 모바일에서 30초 안에 첫 기록을 추가할 수 있어야 한다.
- 사용자는 시간 범위 선택 후 2번 이하의 탭으로 카테고리를 적용할 수 있어야 한다.
- 사용자는 이번 주 카테고리별 총 시간을 별도 설명 없이 이해할 수 있어야 한다.
- 사진 권한을 허용한 사용자는 기록 시간대 사진을 자연스럽게 확인할 수 있어야 한다.
- 데스크톱 웹에서 모바일 기록을 열람할 수 있어야 한다.

### 제품 기준

- 사용자는 하루 기록 완성률을 확인할 수 있어야 한다.
- 사용자는 미기록 시간이 얼마나 남았는지 확인할 수 있어야 한다.
- 사용자는 낭비한 시간 또는 줄이고 싶은 카테고리의 주간 총합을 확인할 수 있어야 한다.
- 사용자는 주간 회고 메모를 남길 수 있어야 한다.
- 사용자는 사진이 없어도 기록 기능을 정상적으로 사용할 수 있어야 한다.

### 기술 기준

- 모바일 앱에서 오프라인 상태로 기존 기록 조회와 편집이 가능해야 한다.
- 네트워크가 복구되면 모바일 기록이 서버와 동기화되어야 한다.
- 데스크톱 웹은 동기화된 기록을 조회할 수 있어야 한다.
- 사진 원본은 자동 업로드하지 않아야 한다.
- CSV 파일로 기록 데이터를 내보낼 수 있어야 한다.

## 11. 핵심 원칙

### 모바일 우선

기록 입력은 모바일 앱을 기준으로 설계한다. 데스크톱 웹은 열람과 회고를 보조한다.

### 기록 우선

기본 화면과 기본 행동은 계획 생성이 아니라 실제 기록 추가에 맞춘다.

### 사진은 보조 단서

사진은 자동 일기장이 아니라 시간 기록을 떠올리는 단서다. 원본 업로드와 과도한 사진 접근은 피한다.

### 프라이버시 우선

시간 기록과 사진은 민감한 개인 데이터다. 사진 원본은 기본적으로 기기에 남기고, 웹 표시가 필요한 경우 작은 썸네일만 명시적으로 동기화한다.

## 12. MVP 완료 정의

다음 조건을 모두 만족하면 MVP 완료로 본다.

- 모바일 앱에서 시간 범위를 선택하고 카테고리를 적용할 수 있다.
- 같은 범위를 다시 선택해 수정하거나 삭제할 수 있다.
- 카테고리를 직접 만들고 색상을 바꿀 수 있다.
- 주간/일간 합계가 기록 변경에 맞게 갱신된다.
- 주간 회고 메모가 저장된다.
- 모바일 기록이 계정 기준으로 동기화된다.
- 데스크톱 웹에서 동기화된 주간 기록을 열람할 수 있다.
- 사진 권한 허용 시 기록 시간대 사진 썸네일이 표시된다.
- 사진 권한 거부 시에도 핵심 기록 기능이 정상 동작한다.
- CSV 내보내기가 동작한다.
